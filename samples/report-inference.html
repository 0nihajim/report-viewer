LLMサービングの推論最適化: vLLMとSGLangの比較

本レポートは、実運用における LLM 推論サーバの選定を目的として、 vLLM と SGLang のスループット特性を整理したものである。

1. 前提

計測は単一ノード A100 80GB×1、モデルは 14B 級の dense モデルを想定した。 入力長は 1,024 トークン、出力長は 256 トークンで固定している。

1.1 評価軸

  • スループット（tokens/sec）: バッチ処理時の総処理量
  • TTFT（Time To First Token）: 対話用途での体感速度
  • メモリ効率: KVキャッシュの利用効率

2. アーキテクチャの違い

vLLM は PagedAttention により KV キャッシュを固定サイズのブロックに分割し、 断片化を抑制する。一方 SGLang は RadixAttention によって プレフィックスを共有するリクエスト間で KV キャッシュを再利用する。

プレフィックスの共有率が高いワークロードでは、RadixAttention の効果が支配的になる。

2.1 使い分けの指針

ワークロード推奨理由
バッチ推論（多様な入力）vLLM連続バッチングが安定
Few-shotプロンプト固定SGLangプレフィックス再利用が効く
エージェント（長い共通履歴）SGLang会話履歴の再計算を回避
構造化出力が必須SGLang文法制約デコードが高速

3. 起動例

python -m vllm.entrypoints.openai.api_server \
  --model Qwen/Qwen2.5-14B-Instruct \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.92 \
  --enable-prefix-caching

4. 結論

プレフィックス共有が見込めるエージェント用途では SGLang、 入力が多様なバッチ用途では vLLM が有利という結果になった。 なお両者とも prefix caching を有効化するだけで大きく改善する場合があるため、 まずはその設定を確認すべきである。
